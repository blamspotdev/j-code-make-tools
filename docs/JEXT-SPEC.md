# JEXT — JCode Extension Package (format 1)

A `.jext` is a **ZIP archive** (like VS Code's `.vsix`) that bundles a whole
extension for distribution and on-device install. The JCode app installs an
extension **only** from a `.jext`.

Filename: `<uniqueName>-<version>.jext`, e.g. `jcode.lang.csharp-1.0.0.jext`.

## Contents (files at the zip root — no wrapping top-level folder)

```
extension.jehm          # the header (authoritative metadata; see JEHM-SPEC.md)
extension.yaml          # the manifest: what the extension is, and the ids of what it brings
languages/<id>/language.yaml
templates/<id>/template.yaml + *.sh   # recipe steps, one script per step
presets/<id>/preset.yaml   + *.sh     # run/build presets
engines/<id>/engine.yaml   + *.sh     # debug adapters
media/…                 # icon, samples, walkthrough images
ui/… (e.g. www/)       # web frontend for app/dbmanager types (entry.ui in the .jehm)
lib/…                   # bundled binaries (a debug adapter jar, a native UI apk)
.jext-manifest.json     # generated by `jext pack` — integrity + summary
```

## `extension.yaml` is a header

Anything with a body of its own lives in a file of its own, and the manifest names it by id:

```yaml
languages: [android-xml, gradle]        # -> languages/android-xml/language.yaml
templates: [android-app]                # -> templates/android-app/template.yaml
contributes:
  runConfigPresets: [android-lint]      # -> presets/android-lint/preset.yaml
  debugEngines: [java-debug]            # -> engines/java-debug/engine.yaml
```

An inline map still works everywhere an id does — a two-line language rule does not need a
directory — so a small extension can stay a single file.

### Shell belongs in `.sh`, not in YAML

A scaffold step that writes a build file is mostly a heredoc, and a heredoc reads as shell rather
than as YAML. Any command may instead name a script beside its own manifest:

```yaml
recipe:
  - label: Write settings.gradle.kts
    script: write-settings.sh          # templates/<id>/write-settings.sh
```

The script runs as a file — the extension directory is bound into the runtime at the same absolute
path — so a shell linter can see it and a failure names it.

Values reach a script as environment variables rather than as `{{tokens}}`, because a file cannot
have text substituted into it and still be the file that runs:

| inline token | script variable |
| --- | --- |
| `{{projectDir}}` | `JCODE_PROJECT_DIR` |
| `{{name}}` | `JCODE_PROJECT_NAME` |
| `{{hostStaging}}` | `JCODE_STAGING_DIR` |
| `{{file}}` / `{{dir}}` (presets) | `JCODE_FILE` / `JCODE_DIR` |
| a template input `{{minSdk}}` | `JCODE_INPUT_MINSDK` |
| — | `JCODE_TEMPLATE_DIR`, `{{extensionDir}}` for engines |

A heredoc that needs one of these must be **unquoted** (`<<EOF`, not `<<'EOF'`) with every other
`$`, backslash and backtick escaped — otherwise the value is written out literally.

Excluded automatically: `.git`, `.github`, `node_modules`, `.jextignore`, and the
manifest itself. Add more exclusions via a `.jextignore` (one path-segment/name
per line).

## `.jext-manifest.json`

```json
{
  "jext": 1,
  "uniqueName": "jcode.lang.csharp",
  "name": "C# Language Pack",
  "version": "1.0.0",
  "type": "language",
  "minJCodeVersion": "1.0.0",
  "targetJCodeVersion": "1.0.0",
  "files": [ { "path": "extension.yaml", "sha256": "…", "size": 2042 }, … ],
  "fingerprint": { "algo": "sha256", "value": "<digest>" }
}
```

- `files[]` lists every packaged file with its SHA-256 and size.
- `fingerprint.value` = `sha256( join("\n", sorted "path\tsha256") )`. It is
  **order-independent** and deterministic, so the same source always produces the
  same fingerprint regardless of zip timestamps/ordering.

## Install / verify flow (app)

1. Read `marketplace.yaml`, pick an entry, download its `jext:` file.
2. Open the zip, read `.jext-manifest.json`, recompute each file's SHA-256 and the
   overall fingerprint; reject on mismatch (corruption/tamper).
3. Read `extension.jehm`; reject if `minJCodeVersion` > running app version.
4. Extract to `filesDir/extensions/<uniqueName>/` and register.

Signed fingerprints (publisher keys) are planned; format 1 covers integrity only.
